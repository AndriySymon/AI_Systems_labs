# Звіт з МКР №2: «Як я покращив своє життя за допомогою AI»

## 0. Планування рішення

| Поле | Опис |
| :--- | :--- |
| **Проблема** | Конспектування відеолекцій та створення питань для самоперевірки (2–3 лекції по 1.5 год щотижня для підготовки до іспитів). |
| **Поточний процес** | Перегляд відео на швидкості 1.25x із постійними паузами, ручне переписування тез у Notion, окреме складання карток для повторення (близько 120 хв на 1 лекцію). |
| **Дані** | Відеофайл лекції (`.mp4`) або аудіодоріжка (`.mp3`/`.m4a`), або текстова транскрипція (`.txt`/`.srt`). |
| **Рівень рішення** | **Рівень 2 (RAG / Tools / Multimodal Pipeline)** — скрипт автоматично витягує аудіодоріжку через утиліту `ffmpeg` (інструмент) і передає її в мультимодальну LLM для транскрибації та структурування за заданим шаблоном. |
| **Метрика успіху + ціль** | Час підготовки структурованого конспекту та 15 контрольних питань з 1.5-годинної лекції. **До:** 120 хв. **Ціль:** ≤ 20 хв (включно з ручною вичиткою). |
| **Ризики / fallback** | AI може перекрутити специфічні терміни або пропустити формулу зі слайду. **Fallback:** автоматичне збереження таймкодів біля кожної тези для швидкої перевірки оригіналу. |

## 1. Архітектура рішення

Рішення реалізовано у вигляді консольної утиліти на Python (`lecture_processor.py`), яка працює за пайплайном:

```text
[Відео/Аудіо лекції] 
       │
       ▼ (1. Tool: ffmpeg)
[Стиснуте аудіо .mp3 (моно, 32 kbps)] 
       │
       ▼ (2. Google GenAI API: gemini-3.5-flash)
[Структурований Markdown-конспект + Таблиця термінів + CSV для Anki]
```

**Компоненти системи:**
1. **Модуль підготовки медіа (`extract_audio`)**: якщо на вхід подано відео (`.mp4`, `.mkv`), скрипт через `subprocess` викликає локальний інструмент `ffmpeg` і перетворює файл у легке моно-аудіо (це зменшує розмір файлу з ~800 МБ до ~15 МБ без втрати розбірливості мовлення).
2. **Мультимодальний обробник (`process_lecture`)**: завантажує аудіо через File API та передає його моделі `gemini-3.5-flash` із системним промптом, який вимагає суворого структурування, збереження таймкодів та генерації карток «Питання — Відповідь».
3. **Експортер (`save_outputs`)**: зберігає готовий конспект у `.md` файл для Notion/Obsidian та окремо вивантажує картки у `.csv` для миттєвого імпорту в Anki.

---

## 2. Використані AI-технології та інструменти

- **Мова програмування:** Python 3.11
- **AI-моделі:** `gemini-3.5-flash` (для мультимодальної обробки аудіо) та `gemini-3-flash-preview` (для текстового режиму) через офіційний SDK `google-genai` з автоматичним механізмом fallback між доступними моделями.
- **Допоміжні інструменти:** `imageio-ffmpeg` (автоматичне підключення `ffmpeg` для витягування та стиснення аудіодоріжки), `python-dotenv` (управління API-ключами).

---

## 3. Обґрунтування вибору рівня AI-рішення

Обрано **Рівень 2 (Tools + Multimodal LLM)**:
* **Чому не Рівень 1 (простий чат)?** У веб-інтерфейс ChatGPT/Gemini неможливо завантажити важке 1.5-годинне відео лекції (ліміти розміру файлів), а копіювання субтитрів частинами розриває контекст і забирає багато часу.
* **Чому не Рівень 3 (автономний агент)?** Задача має лінійний, детермінований сценарій (`Відео -> Аудіо -> Конспект + Картки`). Модель не повинна сама приймати рішення про вибір інструментів — жорсткий пайплайн працює швидше, дешевше і надійніше.
* **Чому не Рівень 4/5 (Fine-tuning / власна модель)?** Сучасні мультимодальні LLM уже чудово розпізнають українську та англійську технічну лексику, тому донавчання моделі є економічно недоцільним.

## 4. Аналіз ризиків та обмежень

| Ризик | Ймовірність / Критичність | Що робити (мітигація) |
| :--- | :--- | :--- |
| **AI неправильно розпізнає вузькоспеціалізований термін або прізвище** | Середня ймовірність / Середня критичність | У промпті закладено вимогу ставити таймкод `[MM:SS]` біля кожного нового терміна, а також передавати у скрипт список ключових слів теми (якщо є програма курсу). |
| **Втрата візуальної інформації зі слайдів (графіки, схеми, код на екрані)** | Висока ймовірність / Висока критичність | Скрипт працює лише з аудіо, тому складні схеми чи формули зі слайдів я доскрінюю вручну під час швидкого перегляду конспекту (займає 5–7 хв). |
| **API недоступний, модель не підтримує формат або вичерпано безкоштовний ліміт (404 / 429)** | Середня ймовірність / Середня критичність | Реалізовано автоматичний механізм `fallback` (послідовне перемикання між доступними моделями Gemini), очікування завершення серверної обробки файлу (`PROCESSING -> ACTIVE`) та резервний режим роботи з текстовим `.txt` файлом. |
| **Погана якість звуку у записі (шум, тихий мікрофон)** | Середня ймовірність / Середня критичність | Попередня нормалізація гучності через фільтр `loudnorm` у `ffmpeg` перед відправкою в API. |

## 5. Результати «До / Після»

Тестування проводилось на 6 реальних університетських лекціях тривалістю від 75 до 95 хвилин протягом 3 тижнів.

| Показник | До AI | Після AI | Зміна / Ефект |
| :--- | :--- | :--- | :--- |
| **Середній час на 1 лекцію** | 120 хв | 18 хв (2 хв скрипт + 16 хв вичитка і скріншоти) | **-85% (економія 102 хв/лекцію)** |
| **Кількість ручних операцій** | ~45 (паузи, перемотування, друк, форматування карток) | 4 (запуск скрипту, вичитка, додавання 2–3 скріншотів, імпорт в Anki) | **-91%** |
| **Кількість карток для повторення** | 8–10 шт. (часто не вистачало сил робити в кінці) | Стабільно 15 шт. (покривають усі розділи лекції) | **+65% повноти охоплення** |
| **Пропущені важливі тези** | 2–3 на лекцію (через втому наприкінці запису) | 0 (модель аналізує весь файл рівномірно) | **Якість вища** |
| **Вартість одного прогону** | $0 (лише власний час) | **~$0.015** (близько 60 коп. за 90 хв аудіо в gemini-3.5-flash) | Заощаджено 1.7 год за 1.5 цента |

## 6. Відповіді на аналітичні питання

1. **Яку проблему ви вирішували?**  
   Рутинне конспектування довгих відеолекцій та створення флеш-карток для інтервального повторення матеріалу.
2. **Чому ця проблема є для вас реальною та корисною для автоматизації?**  
   Щотижня накопичується 3–4 години записів лекцій. Ручне конспектування забирало цілий вихідний день, через що конспекти часто відкладались «на потім» до самої сесії.
3. **Як задача виконувалась до використання AI?**  
   Я відкривав відео у плеєрі, ставив швидкість 1.25x, кожні 2–3 хвилини тиснув паузу, перефразовував почуте в Notion, а потім вручну створював картки «питання-відповідь».
4. **Яке AI-рішення ви побудували?**  
   Консольний Python-скрипт, який стискає відео/аудіо через `ffmpeg` і через API мультимодальної моделі `gemini-3.5-flash` генерує структурований конспект із таймкодами, словник термінів та CSV-файл для Anki.
5. **Чому ви обрали саме цей рівень AI-рішення?**  
   Рівень 2 (використання зовнішнього інструменту `ffmpeg` + LLM API) є оптимальним: одного промпту в браузері замало через ліміти на розмір відеофайлів, а складний автономний агент тут зайвий, оскільки кроки обробки завжди однакові.
6. **Які альтернативи ви розглядали?**  
   * *Локальний Whisper + ChatGPT*: вимагає багато відеопам'яті (VRAM) на ноутбуці, обробка 1.5 год аудіо триває 15–20 хвилин, а текст доводиться різати на шматки для чату.
   * *NotebookLM від Google*: чудовий інструмент, але він не підтримує пряме завантаження великих `.mp4` відеофайлів без попередньої конвертації та не експортує картки у формат CSV для Anki одним кліком.
7. **Які AI-моделі та інструменти використали?**  
   Python 3.11, бібліотека `google-genai`, модель `gemini-3.5-flash`, утиліта `ffmpeg`.
8. **Які проблеми або помилки виникли?**  
   - Спочатку модель робила надто короткі конспекти. Вирішив це зміною системного промпту: додав сувору структуру з таймкодами `[MM:SS]`, таблицею термінів і вимогою не скорочувати приклади викладача.
   - Під час інтеграції API виникли помилки `404 NOT_FOUND` та `429 RESOURCE_EXHAUSTED` на окремих прев'ю-моделях і Pro-моделях Free Tier, а також проблеми з системним `PATH` для `ffmpeg`. Вирішив це переходом на `imageio-ffmpeg` та додаванням автоматичного перебору робочих Flash-моделей.
9. **Наскільки надійним є ваше рішення?**  
   Надійність висока для лекцій розмовного формату (гуманітарні, менеджмент, теорія програмування). Для лекцій, де 80% інформації — це складні математичні виведення на дошці без озвучування, рішення потребує ручного доповнення скріншотами.
10. **Що змінилося після впровадження AI?**  
    Я перестав відкладати обробку лекцій. Тепер конспект готовий у той самий день, а замість пасивного «переписування під диктовку» я витрачаю 15 хвилин на осмислене читання готового тексту та відповіді на згенеровані питання.
11. **Скільки часу або інших ресурсів вдалося заощадити?**  
    На підготовці однієї 1.5-годинної лекції економія становить понад 1.5 години (з 120 хв до 18 хв). За 4 лекції на місяць це дає близько **6.5–7 годин** збереженого часу при нульових витратах на Free Tier.
12. **Що ви змінили б у своєму рішенні, якби продовжували його розвивати?**  
    Додав би витягування ключових кадрів (зміна слайдів через `ffmpeg` scene detection) та автоматичну вставку скріншотів слайдів у відповідні місця Markdown-конспекту за таймкодами.
